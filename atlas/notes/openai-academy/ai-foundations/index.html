OpenAI Academy AI Foundations

Перевірено 2026-11-22. Конспект публічної програми. Теми програми охоплюють основи генеративного AI і LLM, використання ChatGPT, точніший опис задачі, додавання контексту й перевірку виходів.

Концепція Проєктне застосування
Task framing Передавай мету, контекст, джерела, формат і критерії приймання як окремі поля task contract.
Prompt iteration Змінюй одну вимогу або приклад за раз. Фіксуй, який кейс провалився й чи зміна його виправила.
Review Людина звіряє обіцянки та висновки з джерелами. Код може перевіряти типи, обов’язкові поля й доступність артефактів.
Повторювана робота Пакуй вдалі процедури як версіоновані шаблони. Мінімальна перевірка має відрізняти готову відповідь від блокера.

Практика · для FITGYM задай release goal і SHA. Вимагай evidence refs і частковий verdict, якщо тестів для цього SHA немає. Порівняй результат із запитом без SHA та критеріїв.

Доповнення за уроками 1.1–3.2

  • Для практики обрано підготовку короткого звіту про готовність релізу.
  • LLM може генерувати правдоподібний висновок без належного обґрунтування. Для release readiness додай вимогу про джерело кожного твердження, commit SHA і явний статус «доказів бракує».
  • Шаблон курсу Task, Context, Expectation застосовано так. Task — підготувати зведення. Context — власник релізу вирішує, чи готовий кандидат, перевірки PR і CI мають стосуватися точного SHA. Expectation — три пункти: підтверджені перевірки, відсутні докази, наступна дія.

Доповнення за уроками 3.3–5.2

  • Оцінюй чернетку окремо за повнотою, логікою, достовірністю та відповідністю аудиторії. Відокремлюй підтверджені висновки від питань до відповідального.
  • Для точної роботи додай конкретний документ, уривок, шаблон або актуальне джерело. Пам’ять і сталі інструкції використовуй для повторюваних уподобань. Факти поточного релізу перевіряй за артефактами поточного запуску.
  • Перед передачею даних перевір три речі: чи доречний сам тип задачі, чи джерела дозволені й мінімально необхідні та якою має бути людська перевірка.
  • У Orchestrator починай із класифікації задачі. Для release readiness перевір tenant scope, commit SHA і джерело статусу. За відсутності доказів поверни partial і сформуй коротке питання до власника релізу.

Практичні перевірки модулів 4 і 5: по 5 правильних зіставлень із 5.
