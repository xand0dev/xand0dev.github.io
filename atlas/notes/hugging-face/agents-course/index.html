Hugging Face Agents Course — конспект і рішення для Orchestrator

Дата перевірки 2026-11-22. Оригінальний конспект за відкритими матеріалами.

Блок Підхід у матеріалах Hugging Face Застосування для Orchestrator
Агент і середовище Модель вибирає дію, застосунок виконує її, результат стає спостереженням для наступного кроку. API оркестратора фіксує tool request, policy verdict і фактичний результат. Успішне завершення підтверджує стан середовища.
Повідомлення та tools Різні ролі й формати відділяють інструкцію, крок інструмента і його результат. Передавай структуровані observations із request ID. Опис інструмента пояснює семантику, схема перевіряє введення, а gateway перевіряє доступ.
ReAct і завершення Агент уточнює наступну дію з урахуванням попередніх спостережень. Задай ліміт кроків, таймаут і budget. Audit зберігає дії й наслідки, достатні для перевірки.
smolagents Легкі агентські абстракції, зокрема дії через код або виклики функцій. Для MVP обери іменовані read-only функції. Розглядай виконання коду після появи окремого sandbox і контрактів доступу.
LlamaIndex Компоненти пошуку, tools та workflows зручно поєднувати навколо джерел. Використай незалежний пошуковий адаптер із tenant ACL, версією документа і точними посиланнями на знайдені фрагменти.
LangGraph Workflow моделюється станом, вузлами та переходами. Явні вузли Fetch → Validate → Review → Notify. Гейт review має бути видимим станом, який відновлюється після перезапуску.
Agentic RAG Агент може обрати, яке джерело опитати, переформулювати запит або уточнити брак доказів. Почни з фіксованого пошуку. Один повторний пошук дозволяй за слабкого покриття критеріїв. Результат має зберегти query, refs, ранги й прогалини.
Observability Траси підтримують відтворення помилок і виявлення регресій. Зберігай окремі метрики відповіді, tool usage, permissions, latency і cost per accepted report.
Фінальний проєкт Потрібний власний агент і оцінка на benchmark. Курс описує поріг 30%. Для власного портфоліо додай незалежний eval release readiness з дублікатами, відсутнім CI і SHA mismatch. Результати власного eval веди окремо від результатів Hugging Face.

Наскрізний приклад

Запит «чи готовий реліз?» фіксує commit SHA. Один reader отримує PR, другий CI. Якщо CI зелений на попередньому SHA, verifier повертає partial і додає refs на обидва записи. Якщо додатковий пошук нічого не змінює, процес завершується з причиною. Дозвіл на deployment належить власнику релізу.
