Патерни
оркестрації

Шість способів скласти агентів у систему, від найпростішого до найдорожчого. Натисни «Запустити», щоб побачити, як рухається робота. Таблиця з конспекту, схеми мої.

Який патерн мені потрібен?

Кроки задачі відомі наперед?

Кроки незалежні одне від одного?

Різні типи вхідних задач потребують різних виконавців?

Є чіткий критерій якості, за яким можна відхилити результат?

Спершу спробуй одного агента з кращим промптом. За даними Anthropic, мультиагентні системи зазвичай витрачають у 3–10 разів більше токенів на ту саму задачу (джерело). Задачі, що йдуть годинами, додатково потребують checkpoints.

1Ланцюжок

Етапи відомі заздалегідь. Між ними стоять schema gates, тож зламаний крок зупиняє ланцюжок одразу.

У матеріалах Anthropic
Chaining, фіксована послідовність
Для Orchestrator
Intent → план → виконання → перевірка
Коли підходить
Наперед відомі етапи, schema gates

2Маршрутизація

Класифікатор обирає дозволений профіль агента. Коли впевненості бракує, задача йде на fallback до людини.

У матеріалах Anthropic
Routing, вибір спеціалізації
Для Orchestrator
Категорія задачі → дозволений agent profile
Коли підходить
Є контрольні приклади й fallback

3Паралельність

Незалежні читання йдуть одночасно, кожне зі свого джерела. Бюджет резервують до старту, бо паралельні виклики дорожчі.

У матеріалах Anthropic
Паралельність
Для Orchestrator
Незалежні запити PR та CI
Коли підходить
Окремі джерела, контроль витрат

4Оркестратор і воркери

Кількість частин невідома наперед. Планувальник сам ділить задачу, контролер перевіряє scope і глибину, інтегратор зводить результат.

У матеріалах Anthropic
Orchestrator–workers, динамічна декомпозиція
Для Orchestrator
Планувальник пропонує кроки з залежностями
Коли підходить
Наперед невідомі частини й відтворюване приймання

5Evaluator–optimizer

Reviewer відхиляє за rubric, автор має одну правку. Чіткий критерій і ліміт повторів не дають циклу крутитися вічно.

У матеріалах Anthropic
Evaluator–optimizer, керована ітерація
Для Orchestrator
Reviewer відхиляє звіт за rubric і дозволяється одна правка
Коли підходить
Є чіткий критерій і ліміт повторів

6Довгий запуск з checkpoints

Стан і refs на артефакти лежать у БД. Після збою запуск продовжується з останнього checkpoint, а зовнішні дії звіряються, щоб не задвоїтись.

У матеріалах Anthropic
Довгий запуск з checkpoints
Для Orchestrator
Відновлення з БД і refs на артефакти
Коли підходить
Зовнішні дії мають reconciliation
